What changed and why it matters

Kong Royale runs in a web browser, so the computer has to fit the whole game in memory while you play. This page starts with the changes that matter most, says in plain words what you will notice in the game, and links to the technical tabs for the detail. Every number names what was measured and where.

1

A 16 GB Mac can play a whole match in Safari

Before, the game kept every location it had built, so memory only went up. Safari closed the tab (killed for memory) about 80 seconds after the player landed. The game now keeps at most four locations at a time and drops the farthest ones as the player moves on. In the newest test below it reached the results screen both times, with peak memory about 1 GB lower than the version before it.

What you'll notice: on a 16 GB Mac in Safari, the match no longer ends with the tab closing on you.

Mac mini M4, 16 GB, Safari 27, quality Auto (picked Low), ?seed=42, scripted moving player, production build served locally. Newest: main 3248912, 2 runs. Before: main 1ee1f52, 1 run. Details in the Safari panel below.

Changes: #140, #149, #157, #160

2

Textures are stored smaller, with no visible loss at the default

The game now shrinks the textures (the pictures wrapped around 3D objects, like the stone on a temple wall) to 1024 pixels on their longest side, or to 512 pixels in Safari and on low-memory computers. In a test with four heavy locations loaded at the title, texture memory fell from 1,751 and 1,735 MB (cap off, two runs) to 1,543 and 1,515 MB at the default, and to 1,387 MB at 512.

What you'll notice: at 1024 pixels we saw no visible loss when comparing views at 3× zoom. At 512 pixels there is slight softening up close only (for example the nearest container logo at 3× zoom), not at normal size.

Memory: memory.mts without a GPU (SwiftShader, 640×360) at the title, 4 heavy locations, runs interleaved; WebGL textures 1751.4 and 1735.4 MB off, 1542.8 and 1514.8 MB default, 1387.1 MB at 512 (fork #158). Look: Kong RTX on Windows (D3D11), views compared at 3× crops (RAY-140, RAY-141).

Changes: #154, #156, #158

3

Coming back to the game after minimising is faster in Safari

Safari stops drawing frames for a hidden window, and the game used to wait for those frames before it carried on loading. It now keeps going without them. After a window had been minimised for 120 seconds, the time until the game was ready again went from 9.9 s to 2.2 s.

What you'll notice: switching away and back lands you in the game in about 2 seconds instead of about 10.

A/B of fork #37 in Safari, recorded on RAY-112 (minimised for 120 s, time to ready). The machine and number of runs are on that issue, not on this page.

Changes: #37

Words used on this page

Memory
The working space a program uses while it runs. A browser tab that uses too much of it gets slow, or gets closed.
Killed for memory
Safari (and other browsers) close a tab that grows past a limit instead of letting the whole computer slow down. For a player, the game simply disappears mid-match.
WebContent
The part of Safari that runs the game's page. Its size is the number to watch, because it is the part Safari closes.
Location (streaming a location)
A named place on the island, such as a harbor or a temple. The game builds each one as the player gets close, which is called streaming it in. A location the game has built and still holds is called resident.
Texture
A picture wrapped around a 3D object, like the stone pattern on a temple wall. Big textures look sharper and use more memory, mostly on the graphics card (GPU memory).
Frame time
How long the computer takes to draw one picture of the game. Smaller is smoother, and a long one shows up as a stutter. The Performance tab is full of these.

The journey so far

  1. Nov 3 #37 Safari keeps loading when its window is hidden, instead of waiting for frames it will not draw.
  2. Nov 5 #140 Low-memory mode builds the locations in view from the starting islet and the plane, and measures range along the ground.
  3. Nov 5 #149 Low-memory mode drops the farthest locations once a match is in play, so memory stops climbing.
  4. Nov 5 #154 A texture size cap is added behind a flag (off by default).
  5. Nov 5 #156 The harbor locations' painted textures follow the same cap.
  6. Nov 5 #157 Locations are ranked by where the player will be in 5 seconds, and builds are spaced out while moving fast.
  7. Nov 5 #158 The texture cap turns on by default: 1024 pixels, or 512 in Safari and on low-memory computers.
  8. Nov 5 #160 Building a location and dropping one now use the same ranking. In the Safari test, both runs reached Results and peak memory fell by about 1 GB.
